# Stock vLLM vs program-level priority (job 60827432, A100-40GB, 1 rep, 300 s measured)

vLLM 0.33 `--scheduling-policy priority` with priority = task start time (ms), against `fcfs` (stock).
Neither pins KV, so this isolates scheduling order. GPU KV pool: 139,232 tokens for both servers.

Caveats:
- 1 rep. Task percentiles cover only tasks that started after warm-up and finished inside the 5-minute window. Stock finishes fewer, so its p95 is biased low, and the priority advantage is probably understated.
- Prefix hits stay near 0% for both. vLLM's priority policy reorders and preempts, but it doesn't protect a paused agent's KV. The simulator's "always-keep" (pinning) has no real-vLLM counterpart here. The closest is Continuum's fork (`--scheduling-policy continuum`, program FCFS + 2 s pin), which is now buildable in `continuum-env`.
