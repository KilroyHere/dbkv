# Prior art: KV retention and scheduling for paused (tool-calling) agents

Compiled 2026-11-04 from the papers themselves: arXiv abstract and HTML full text, plus docs/README pages where those are the source. Where a claim could not be checked against the source, it says **unverified**. Continuum Fig. 16 is a bar plot whose values are not in the text, and the PDF could not be rendered here, so its magnitudes are unverified.

The three questions:
- **(1)** Is program- or agent-level FCFS (or another program-aware scheduler) shown to be the main win?
- **(2)** Is "always keep KV during tool calls" shown to match or beat TTL- or prediction-based policies?
- **(3)** Does anyone show that knowing tool durations adds little?

## Verdict

1. **Partially shown.** The pieces exist. Program- or request-arrival ordering is used and partly credited (InferCept: 24.5% from keeping arrival order; Continuum Fig. 16 ablation; Sutradhara bakes it into its baseline). Keep-under-pressure without prediction beats TTL in ThunderAgent and in the Stony Brook project. InferCept finds an elapsed-time estimate within 93% of the oracle.
2. **Not shown anywhere:** the exact combination "always-keep + program-FCFS ≈ duration-oracle", decomposed so that most of the gap to stock vLLM is scheduling, not TTL. Continuum has no infinite-TTL arm, and no paper compares against an oracle under program FCFS.
3. **Counter-evidence to address:** *Ask the Tool* (2609.18849) finds keep-all-like predictors up to 25% worse than LRU (GPU-only, coding tools, no program FCFS) and argues against pre-call estimates. dbkv should show whether program FCFS is what makes keep-all safe.
4. **Not new:** the observation that Continuum's released code is a fixed 2 s pin (2608.30830 App. F.1 already uses and states it), and a per-hardware retain-vs-discard break-even (same paper, Table 3).
5. **Still new for SQL agents:** (a) the system-level pause-length crossover at which always-keep stops matching the oracle under program FCFS, on calibrated SQL pause distributions; (b) `EXPLAIN` cost as a *pre-call* duration signal, tested against no-signal and against oracle durations (nobody uses a query optimizer; *Ask the Tool* argues pre-call is hopeless); (c) a measured released-Continuum vs always-keep comparison with the scheduling win separated from the TTL win.
