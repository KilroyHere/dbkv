# Prior art: schema briefs, schema linking cost, and schema-prefix caching for SQL agents (D2)

Compiled 2026-11-05 from the papers themselves (arXiv abstract plus HTML full text, method and evaluation sections). Where a claim could not be checked against the source, it says **unverified**. Venues come from the arXiv comment field, the venue's own site, or the paper header; any other venue is marked unverified. Numbers in figures only (not in text or tables) are not quoted.

The audit asks, for each paper: what it selects or summarizes and how; whether it reports latency, turns, tokens or cost (and the numbers); whether it is agentic (multi-turn tool use) or single-shot; whether it uses gold information; and its delta vs dbkv D2 (an automatically built per-database brief in the system prompt of a Qwen3-8B ReAct agent on BIRD dev, measured on turns, p50/p95 latency, accuracy and prompt tokens, including under concurrency with a shared, prefix-cached brief).

## Verdict

1. **Already shown.** Single-shot schema pruning cuts tokens and calls (RSL-SQL keeps 83% fewer columns at 94% strict recall; AutoLink links in 8K tokens; bidirectional retrieval takes 2.6 s vs 47 s for CHESS). A gold schema lifts small-model accuracy by about 11 points on BIRD (Qwen2.5-7B: 37→48%). Agents over-explore, and grounding cuts exploration: Sophrosyne reports 4.6× less over-exploration, the agent-first paper 18% fewer queries with expert hints, AgentSM 1.7 fewer steps and 78 s less mean latency with memory. Full-schema ReAct is fast with a frontier model (ReAct-SQL, 7.5 s median).
2. **Open (1): turns and latency in a multi-turn agent from an automatic, gold-free brief.** No paper reports downstream agent turns plus p50/p95 latency for full vs oracle vs automatic schema context. Sophrosyne (tokens and accuracy only, uses BIRD evidence) and the agent-first paper (oracle hints, query counts) come closest.
3. **Open (2): behaviour under concurrency and KV pressure.** Every paper measures one request at a time (TableCache uses batches but reports only total TTFT). None reports throughput, preemption or KV use as brief size and agent count grow.
4. **Open (3): a shared per-database brief cached as a prefix across concurrent agents.** TableCache is the only schema-KV-reuse paper, and it is single-shot, reorder-oriented and prefill-only. Prompt Cache and SGLang never use DB schemas. D2's "brief first, so prefix caching hits" design is untested.
5. **Surprise:** in the papers we read, the gain from gold schema scales inversely with model strength. ReFoRCE (o3, Spider 2.0) gets +0.37 EX from gold tables, and CHESS and Death-of-Schema-Linking drop linking on BIRD. For an 8B agent the gap is large (D2: +18 points; 2510.14296: +11 points). D2 should state that its claims are for small, self-hosted models.
6. **Baselines dbkv should include:** (a) no brief, i.e. pure exploration (have); (b) full schema plus samples (have; this is ReAct-SQL's setting and BridgeScope's small-DB `get_schema`); (c) gold oracle (have; matches the "perfect schema" of 2510.14296 and the gold-table arms of RSL-SQL, ReFoRCE and AgentSM); (d) embedding top-k retrieval (BGE-style, as in AutoLink's first stage and DE-SL); (e) a cheap one-call LLM table→column selector (C3/RSL-forward style); optionally (f) a Sophrosyne-style "irrelevant tables" directive in the `list_tables` reply, to separate prefix-brief effects from tool-reply steering. Report strict recall and columns kept, as RSL-SQL and AutoLink do, so selection quality is comparable.
