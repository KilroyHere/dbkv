# Prior art: prefix-aware routing and agent admission across replicas

Compiled 2026-11-05 from the sources themselves: arXiv abstract and HTML full text, the ICLR proceedings, and project docs and source code on GitHub (`curl` of raw files on `main` as of today). Where a claim could not be checked against the source, it says **unverified**. Numbers that live only in figures are marked as such.

What we compare against (the dbkv gateway):
- **(A)** whole-task admission control, with the concurrency limit from a KV-memory model;
- **(P)** task-start priority (a resumed turn keeps its task's start time);
- **(R)** routing across vLLM replicas: round-robin vs least-loaded vs **database affinity with a load cap** (pin each DB, whose agents share a per-DB schema-brief prefix, to a home replica; spill when the home is overloaded).

Columns: what it routes or schedules on and how; whether load is capped so a hot prefix cannot swamp one replica; what it reports and in what setting; whether it handles multi-turn agents or task-level admission; the delta against our gateway.

## Verdict

1. **Already shown:** prefix/cache-aware routing beats round-robin or random by large factors when shared prefixes dominate: Preble 1.5–14.5× avg and 2–10× p99 latency; SGLang 1.9× throughput and 20% → 75% hit rate; llm-d ~170× p90 TTFT vs random and 57× vs approximate near saturation, ~2× throughput. Guarding affinity with a load check is standard (Preble Th_bal + replication, SGLang's abs/rel imbalance switch, Dynamo busy thresholds, SMetric's SLO check), so "DB affinity with a load cap" is not new as a mechanism.
2. **Open:** nobody evaluates **task-level admission + task-start priority together with prefix-affinity routing** for online multi-turn agents. CONCUR has agent-level admission on one engine (offline); SMetric has session pinning with spill but no admission; Dynamo ships ThunderAgent admission and priority hints with no published evaluation. A per-database brief (shared by many concurrent agents) as the affinity key, rather than a session's private context or a learned prefix tree, is also untested.
3. **Baselines we must include:** round-robin, least-loaded, and **SGLang's cache-aware policy** (approximate tree + abs/rel imbalance switch, run with its Python defaults 0.3/64/1.5) as a routing arm, reimplemented in our gateway if we stay on vLLM. Report hit rate and p95 TTFT as well as task latency, so the result is comparable with Preble and llm-d.
